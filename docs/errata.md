# Errata

Contradictions and errors found in the Thermia Modbus protocol document 17.1, behaviour of
the reference pump that the document doesn't describe, and how the library handles each.
Chapter 3 (address list) wins unless a row below records otherwise, with its evidence: a
register dump or the display of the reference pump, another edition of the document, or a
field report from another pump.

## Register entries

| Register | Issue | Resolution |
| -------- | ----- | ---------- |
| Coil 25 "Enable additional heater only" | Scale 1 in chapter 3, scale 100 in chapter 4. | Scale 1 (chapter 3; coils are bits). |
| Holding registers 61–63 "Gear shift delay heating / pool / cooling" | Unit listed as `min`; the reference pump reads 300, 300 and 60. The display shows the heating delay (300) as "Schakelvertraging 0:05:00" (2026-10-25). | Seconds (`unit="s"`), as the display shows; the protocol document 17.0 and the Mega & Mega E edition of 17.1 ("Modbus protocol for Mega & Mega E, Genesis platform, Version 17.1", ACME01UG01202; PDF dated 2025-12-04) list all three in `s`. |
| Holding register 30 "Cooling mix valve set point (EM)" | Unit listed as `%`, but it is the display setting "Gewenste koelaanvoer min." (desired cooling supply minimum, 18 °C): on 2026-10-25, changing it on the display to 19 °C made holding 30 read 1900 while holding 105 "Start temp for cooling" stayed 1800, and no other holding register changed. | `°C` at scale 100, with `nan=ABSENT_SENSOR`; the protocol document 17.0 and the Mega & Mega E edition of 17.1 ("Modbus protocol for Mega & Mega E, Genesis platform, Version 17.1", ACME01UG01202; PDF dated 2025-12-04) list it in `°C`. |
| Holding register 125 "Input power limit during Power Limitation" | The description calls itself "defacto 40125", but its de facto address is 40126; 40125 is register 124, whose own description refers to 40126 for the power limit. | Address 125 (the Address column). |
| Input register 137 "Mix valve cooling opening degree (EM2/3)" | Chapter 7 lists the unit as `on/off` for an opening degree; chapter 3 lists `%` at scale 1. A Calibra Cool reads 0 to 10000 from a closed to a fully open valve (CJNE/thermiagenesis#284), so the scale is 100. The reference pump reads 0 outside the cooling season. | `%` at scale 100. To be verified on the reference pump while passive cooling runs. |
| Coil 14 "Enable hot gas pump" and the HGW registers: coil 6 "Enable HGW", discrete 52 "HGW sensor alarm", discrete 223 "HGW regulation control signal", input 45 "HGW supply line temperature" | Listed only in chapter 6 (coil 14 in 6.1, the others in 6.2), not in chapter 3. The reference pump has no HGW: the coils and discrete inputs read `False`, input 45 reads 20000. | Mapped from chapter 6. |
| Input register 47 | Chapter 6 lists it twice: as "Tap water valve position (%)" (as in chapter 3) and as "HGW mix valve position (%)". The reference pump reads 0. | "Tap water valve position" (chapter 3). |
| Input registers 119–120 "Pool supply/return line temperature (EM)" | Listed in chapter 8 only, not in chapter 3 (holding 119–120 are different registers). The reference pump has no pool: both read 20000. | Mapped from chapter 8. |
| Holding register 58 "Pool charge set point (EM)" | Unit `°C` in chapter 8, `%` in chapter 3. The reference pump, which has no pool, reads 2600: 26.00, a typical pool temperature. | `°C` (chapter 8, supported by the dump), with `nan=ABSENT_SENSOR` like the other temperatures. To be verified on a pump with a pool. |
| Input registers 78–80 "Electric meter L1/L2/L3 power (W)" | The document doesn't say whether the power can be negative. The meter needs the current limiter, which measures the house connection, so a house that exports (for example with solar panels) may report negative power. The reference pump has no meter. | Signed, so export reads as negative watts instead of about 65000 W; a phase of a house connection stays far below 32767 W. To be verified on a pump with a meter and solar panels. |
| Input registers 83–84 "Electric meter kWh total" | LSB listed before MSB, the reverse of every other 32-bit pair. The reference pump has no electric meter (both read 0). Field report: users of another integration saw wrong kWh totals while it read MSB first (CJNE/thermiagenesis#292; a Calibra, firmware 16.00 per a later comment), and pythermiagenesis switched to LSB first at scale 10 (CJNE/pythermiagenesis#3), but no correct reading after that switch has been reported. | LSB first, as documented. To be verified on a pump with an electric meter (17.1). |

## Document-wide

| Topic | Issue | Resolution |
| ----- | ----- | ---------- |
| Scale 100 (chapter 2.1) | The scale table says the transmitted value is "a tenfold larger"; the worked example in the same section transmits -5 °C as -500. | Hundredfold (the worked example; the reference pump's discharge pipe reads 2667: 26.67 °C, not 266.7 °C). |
| Footnote \*5 "Should always be set to 1 i auto mode" | Printed under the coil table of chapter 3 and with the footnotes of chapter 9, but no register refers to it. | Not applied to any register. To be verified which register it belongs to. |
| Footnotes | Printed at the end of chapter 9 instead of in their own chapter (as in 17.0). | Treated as document-wide footnotes. |

## Undocumented behaviour

Observed on the reference pump (firmware 17.1.11); the protocol document does not describe it.

| Registers | Behaviour | Handling |
| --------- | --------- | -------- |
| Temperature input registers (scale 100) | A sensor the pump doesn't have reads 20000 (200.00 °C), with no sensor alarm. The reference pump reads it on 12, 27, 40 and 41 (system supply, system return, mix valve 1 supply, buffer tank) while 106 (cooling supply, passive cooling enabled) reads 2224. | 20000 decodes as no value (`nan=ABSENT_SENSOR`). |
| Input register 121 "Room temperature sensor" (scale 10) | A pump without a room sensor reads 2000 (200.0 °C), the scale-10 form of the 20000 above: reported for a Calibra 7 (CJNE/thermiagenesis#268) and by pg-andersson/pgart_t ("the temperature value will be 200"). The reference pump has a room sensor (input 121 reads 229, 22.9 °C, which confirms scale 10); its undocumented inputs 325–328 and 412 read 2000. | 2000 decodes as no value (`nan=ABSENT_SENSOR_AT_SCALE_10`), as for every °C register at scale 10. |
| Holding register 118 "Outdoor temperature sensor" | Reads 20000 (200.00 °C) until a BMS writes it (the reference pump reads 117 = 0, 118 = 20000). A written value takes effect only when holding 117 selects the BMS (infradom/thermia-genesis-calibra-modbus-hints#1), and per its description in chapters 3 and 4 the pump falls back to its own sensor when 118 isn't refreshed within 12 hours. | Decodes as no value (`nan=ABSENT_SENSOR`), like an absent sensor. |
| Input registers 348–365 and 380–397: energy statistics | No edition of the protocol document lists them (7.01 to 17.1, Mega and Athena included). On 2026-10-25 every value matched the energy statistics on the display of the reference pump (#33): per circuit, heating from 348 and tap water from 357 (months 1–12; months 13–24 from 380 and 389), a block of 9 registers with the auxiliary heater, consumed, delivered and natural source energies as pairs of kWh (0–999) and MWh, and the COP at scale 10. For example 350 = 87 and 351 = 1 where the display shows 1.1 MWh consumed, and 354 = 67 where it shows COP 6.7. infradom/thermia-genesis-calibra-modbus-hints first described this range, as day values. | Mapped as the `energy_statistics` subsystem, each energy as `MWh × 1000 + kWh` in kWh. To be verified after 1 November whether months 1–12 roll monthly or per calendar year. |
| Input registers 330–339: "today" statistics | infradom describes them as today's energy and COP per circuit. On the reference pump the COPs (333, 338) matched the display's day view in three comparisons, but the kWh did not: they read 1, 9 and 8 where the display showed 0.8, 6.1 and 5.4 kWh, and later 0 while the display's day values kept rising (#33). | Not mapped. |
| Addresses chapter 3 doesn't list | Every address up to at least 5000 answers in all four spaces: undocumented ones read 0 or `False` (input 28, 999 and 5000, holding 999 and 5000, coils and discrete inputs 999 and 5000), except input 14. It reads like the outdoor temperature (input 13): 1150 next to 1170 earlier, 947 next to 947 in three reads on 2026-10-24, and 1425 next to 1425 on 2026-10-25 while the display showed one outdoor temperature, so it is probably the filtered outdoor temperature (holding 118 says the pump filters it). It is not mapped. Only far outside the map (65000) does the pump raise an illegal-address exception. | Not relied on: the library reads only mapped addresses. Missing subsystems are detected from their Enable coils, not from exceptions. |
